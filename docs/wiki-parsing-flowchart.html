Wiki 解析流程：从文档到结构化知识库

Wiki 是一条异步、LLM 驱动的 Map–Reduce 管线。文档完成解析分块后被排队，批处理器并行地把每篇文档 抽取成实体 / 概念 / 摘要页面，再按 slug 归并写入 wiki_pages，最后经一次防抖的 KB 级收敛重建索引与交叉链接。下图给出完整数据流、每个节点做什么、以及怎么做。

批次调度 · 并发闸门与领取

ProcessWikiIngest

30 秒后触发落到 wiki 工作池。这里解决「同一 KB 多批并发、既不重复处理又不互相饿死」的问题： Redis 模式用行领取 + 每 KB 在途配额，Lite 模式用进程内每 KB 互斥锁。

并发闸门reserveInflightSlot
Redis：每 KB 在途批次上限（默认 4）。Lua 原子占槽，防止单 KB 独占整个 wiki 池。Lite：liteLocks 每 KB 串行。
领取待处理行claimPendingList
Redis：FOR UPDATE SKIP LOCKED 认领不相交的一批（默认 5 篇）；回收 90 分钟过期的崩溃认领。Lite 用 peekPendingList。
按文档去重decodePendingRows
按 knowledge_id 折叠，保留最后一次操作（如「上传后立刻删除」→ 只留 retract）。
加载 KB 调优参数
读取 batchSize / mapParallel / reduceParallel / 抽取粒度，供本批统一使用。
⎇
无行可领 → scheduleStaleClaimRecheck 布置一个越过 90 分钟阈值的安全网触发，避免崩溃批次留下的行永久搁浅；达到在途上限 → scheduleCappedRetry 合并式延后重试。
[]WikiPendingOp（本批 ≤5 篇文档）+ WikiBatchContext（懒加载缓存）

目录规划 · 每批一次

planBatchTaxonomy

reduceSlugUpdates · errgroup(reduceParallel)

ProcessWikiIngest 尾段

把本批成果落地并对认领的行做终态结算：成功删除、失败重排或死信。昂贵的 KB 级收敛不在这里做， 而是记入 finalize 车道推迟合并。

清洗摘要死链sanitizeDeadSummaryLinks

FINALIZE 阶段 · KB 级收敛（防抖合并）

ProcessWikiFinalize

KB 级的昂贵收敛工作过去在每个 5 篇批次尾部都跑一次，现改为每 KB 防抖合并成一次： 一波 N 篇文档只重建一次索引。用 asynq.TaskID + finalize 锁保证同 KB 不并发。

排空 finalize 车道PeekBatch
聚合受影响 slug、交叉链接引用、以及索引变更描述（新增/移除文档）。
▶
重建索引简介rebuildIndexPage
首次：WikiIndexIntroPrompt 采样近 200 篇摘要生成；增量：WikiIndexIntroUpdatePrompt 仅凭变更描述更新。
纯文本收敛（无 LLM，限本批受影响页）
死链清理cleanDeadLinks
ExistsSlugs 批量探测出链，把指向已删/归档页的 [[链接]] 修复或剥离。
交叉链接注入injectCrossLinks
在受影响页正文里，把提到其他页标题/别名之处 linkify 成 [[wiki 链接]]。
↻
处理完 trimPendingList 排空这批 finalize 行；若期间又有新行落入，则 scheduleFinalize 再排一次收敛。
收敛完成 → 索引页 / 交叉链接就绪，Wiki 对用户完全可用
✓

完成 · 结构化 Wiki 知识库

每篇文档现由摘要页 + 若干实体/概念页表示，页面间以 [[wiki 链接]] 互联、归入目录树， 索引页给出全局导览，变更历史记录在日志。前端 WikiBrowser.vue 即渲染此结构。

数据流落点 · 持久化与状态

task_pending_ops
耐久操作队列，两条车道：wiki:ingest（每文档一行，dedup_key=knowledgeID）与 wiki:finalize（受影响 slug / 变更）。取代了会被 24h TTL 清掉的旧 Redis 列表。
wiki_pages
最终产物：entity / concept / summary / index / log 页。含 content、source_refs、chunk_refs、out_links、aliases、folder_id、status(draft→published)。
wiki_folders
目录树；由 Stage 2·5 的目录规划串行创建/复用，Reduce 只读分配。
wiki_log_entries
变更历史流（每事件一行），供日志 feed；批量 AppendBatch 写入避免写放大。
task_dead_letters
超过 5 次重试预算的操作归档于此，人工/巡检可查。
chunks
上游分块正文，Map 阶段重建文档、Reduce 阶段取引用证据的来源。
Redis · slug 锁
wiki:slug:{kb}:{slug} 序列化同 slug 读改写（Phase 3 去掉了每 KB 独占锁后仍保证共享页不丢更新）。
Redis · 在途配额 / 墓碑
wiki:inflight:{kb} 有序集限每 KB 并发批次；wiki:deleted:{kb}:{kid} 删除墓碑让在途任务快速短路。
